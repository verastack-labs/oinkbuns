# Agent rules for oinkbuns

Read this before changing anything in the repo.

## Tooling

- pnpm only, never npm or yarn. Node 22 or newer. The exact pnpm version is
  pinned by `packageManager` in the root `package.json`.
- Phaser is pinned to `3.90.0`. Never upgrade to Phaser 4; the APIs differ.
- Next.js is `16.3.6`. Before writing any code under `landing/`, read
  `landing/AGENTS.md` (generated by `next dev`) and the guides it points at
  in `landing/node_modules/next/dist/docs/`. Next 16 differs from what you
  may remember.
- `pnpm check && pnpm build && pnpm assemble` must pass before any commit
  is pushed. CI runs exactly that.

## Workspace

- `landing/` is the site at `/`. `game/` is the game at `/play/`.
  `scripts/assemble.mjs` merges their build outputs into `dist/`, which is
  what GitHub Pages serves. Never commit `dist/`, `.next/`, `.next-build/`
  or `game/dist/`.
- `game/src/core/` is pure TypeScript game rules and imports nothing from
  Phaser. Everything that touches Phaser lives outside `core/`.
- Every colour on the landing page is defined once in
  `landing/src/app/globals.css`. The game's colours live in
  `game/src/ui/theme.ts`. Both mirror
  `oinkbuns-internal/assets-src/palette.md`.
- Every Play link on the landing page is `href="/play/"`, absolute with a
  trailing slash.

## Where the rules live

- `PRODUCT.md`: what Oinkbuns is, who it is for, what it refuses.
- `DESIGN.md`: how it looks and moves, written from the built result.
- The design spec and the implementation plans are in the private repo
  `verastack-labs/oinkbuns-internal` under `docs/superpowers/`.

## Writing and commits

- No em-dashes anywhere: code, comments, docs, or copy. Use a hyphen or
  restructure the sentence. The one exception is the block `next dev`
  generates in `landing/AGENTS.md`, which is tool output and is never
  edited by hand.
- Commit messages: imperative subject, a body that explains why, and the
  trailer line `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- Testing is deliberately lean: only the tests the spec lists (core rule
  modules, day config schema, the devlog loader). Do not add a browser
  test suite.
- The fan-project disclaimer is used verbatim in `README.md`, `NOTICE` and
  the landing footer. Never reword it.
